# Datasets — ADMET Prediction

Four MoleculeNet datasets, one per ADMET endpoint group, per
`TODO/data/TODO_sources_licensing.md`'s plan. Same download approach as
project #1 (self-downloading via a script, not a manual step — see
`ml/preprocess.py`).

## 1. Solubility — ESOL (Delaney)
- Source: `https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/delaney-processed.csv`
- 1128 compounds. Target: `measured log solubility in mols per litre`.
- Same dataset used in project #1 — reused here rather than switching to
  AqSolDB, for consistency and because it's already validated/well-understood.
- Citation: Delaney, J. S. "ESOL: Estimating Aqueous Solubility Directly from
  Molecular Structure." J. Chem. Inf. Comput. Sci. 44.3 (2004).

## 2. Toxicity panel — Tox21
- Source: `https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/tox21.csv.gz`
- 7831 compounds, 12 binary assay columns (nuclear receptor / stress response):
  `NR-AR`, `NR-AR-LBD`, `NR-AhR`, `NR-Aromatase`, `NR-ER`, `NR-ER-LBD`,
  `NR-PPAR-gamma`, `SR-ARE`, `SR-ATAD5`, `SR-HSE`, `SR-MMP`, `SR-p53`.
  Many missing labels per-compound (not every compound tested against every
  assay) — expected, handled via masking, not imputation, per
  `TODO/data/TODO_preprocessing_pipeline.md`.
- These 12 codes exactly match what's already documented in
  `backend-spec/api-contract.md`'s `toxicity_tox21.panel` field — confirmed
  consistent, no contract update needed.
- Source: Tox21 Data Challenge (NIH/EPA/NCATS), public domain (US government
  work).

## 3. Clinical trial toxicity / FDA approval — ClinTox
- Source: `https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/clintox.csv.gz`
- 1484 compounds, 2 binary columns: `FDA_APPROVED`, `CT_TOX`.
- Matches `backend-spec/api-contract.md`'s `clinical_trial_toxicity` /
  `fda_approval_likelihood` fields exactly.
- Source: derived from ClinicalTrials.gov + FDA data via MoleculeNet,
  permissive for research/educational reuse.

## 4. Blood-brain barrier penetration — BBBP
- Source: `https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/BBBP.csv`
  (note: capitalized filename — lowercase `bbbp.csv`/`.csv.gz` return 403 on
  this mirror)
- 2050 compounds, target column `p_np` (1 = penetrates, 0 = does not).
- Matches `backend-spec/api-contract.md`'s `bbb_penetration` field.

## Known complexity ahead (Sprint 1)

Merging four datasets of very different sizes (1128–7831 compounds) into
one multi-task table by canonical SMILES will produce a LOT of missing
labels per task (e.g. a compound in ESOL almost certainly wasn't tested in
Tox21) — this is expected and exactly why `TODO/data/TODO_preprocessing_pipeline.md`
calls for masking (NaN) rather than imputing missing labels for the
classification tasks.

## Versioning & reproducibility

- **Raw vs. processed separation**: `data/raw/` (gitignored, self-downloaded
  on first run by `ml/preprocess.py::ensure_raw_datasets()`) is kept
  separate from `data/processed/` (`admet_processed.csv` + `report.md`,
  also gitignored — both are regenerated by `python ml/preprocess.py`, not
  committed).
- **Dataset version pinning**: each source is a fixed URL to one specific
  file on the DeepChem/MoleculeNet S3 mirror (`ml/preprocess.py::RAW_SOURCES`),
  not a "latest" API pull — the exact file downloaded today is the exact
  file that will be downloaded a year from now, as long as the mirror keeps
  serving it.
- **Determinism verified, not assumed**: `python ml/preprocess.py` was run
  twice from a fully clean state (`data/raw/` and `data/processed/` deleted,
  forcing a fresh re-download of all 4 sources both times) — both runs
  produced byte-identical `admet_processed.csv` and `report.md` (verified
  with `diff`). `SEED = 42` is fixed throughout (`ml/preprocess.py`'s
  scaffold split, and every downstream ML script that samples or splits).
- **DVC — deliberately out of scope**: the whole processed dataset is one
  ~10k-row CSV (a few MB), not large binary artifacts. DVC's remote
  storage, `.dvc` pointer files, and separate `dvc pull` step would be
  meaningfully more infrastructure than this portfolio-scale project
  needs; the fixed-URL self-download + deterministic `preprocess.py`
  already give the same practical guarantee (anyone can reproduce the
  exact same processed data from scratch) without it. Revisit only if raw
  data sources stop being simple flat-file downloads (e.g. a future
  large-image or trajectory dataset).

## Changelog

Major decisions made while building this dataset (see `TODO/data/` for the
full task-level history):

- **Dataset selection** (ESOL + Tox21 + ClinTox + BBBP, self-downloaded from
  the DeepChem/MoleculeNet S3 mirror rather than via PyTDC): PyTDC requires
  an old numpy without a prebuilt wheel and needs a C compiler to build
  from source, which isn't available in this environment. See
  `TODO/data/TODO_sources_licensing.md` for the full rationale.
- **Salt-stripping** (`ml/preprocess.py::canonicalize`, via RDKit's
  `SaltRemover`): source SMILES sometimes include counter-ions/salts (e.g.
  hydrochloride salts); the largest remaining fragment is kept as the
  parent molecule so the same active compound isn't split into multiple
  near-duplicate rows that differ only by salt form.
  - Same canonicalization function is applied to all 4 sources before merge,
  so "the same molecule" always means "the same canonical SMILES", never a
  per-source string.
- **Stereochemistry dropped** (`isomericSmiles=False` in canonicalization):
  a deliberate first-iteration simplification — stereoisomers are treated
  as the same molecule for merge/split/modeling purposes. This can matter
  for ADMET properties in reality; revisit if a later analysis shows
  stereoisomers behaving very differently on any task.
- **Scaffold split over random split** (`ml/preprocess.py::scaffold_split`,
  Murcko scaffold groups, seed 42, ~70/15/15 train/val/test): random
  splits on molecular data systematically inflate held-out metrics because
  structurally similar molecules (often near-duplicates by scaffold) leak
  across splits; scaffold split is the de-facto standard in ADMET/drug
  discovery literature for a realistic generalization estimate. Verified
  empirically (not just assumed) in `ml/data_quality_report.py`: zero
  scaffolds span more than one split, and zero duplicate molecules appear
  across train/val/test.
- **Missing labels masked, never imputed**: the 4 source datasets barely
  overlap by molecule, so most rows have a real label for only one task —
  masking (`NaN`, skipped per-task per-row) avoids inventing labels for
  tasks a molecule was never tested on.
